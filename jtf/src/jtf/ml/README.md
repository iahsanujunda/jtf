A run is made in Dagster, by hand: `ads/ads_ml_prediction_solar` with its config (`mode`; a backtest's test months, a what-if's target days, a reproduce's original run), then `ads/ads_ml_outcome_solar`; a backtest also `ml/solar_backtest_metrics` (see [orchestration](../orchestration/README.md)). A model declares its name, its version, the feature columns it reads and the inputs those are made from (`MODELS` in replay.py): persistence reads `solar_d2_mw`, made from `actuals_d2`; the seven-day mean reads `solar_mean_7d_mw`, made from `actuals_7d`. A run reads and fingerprints its own model's columns and no others, so a feature added for one model leaves every other model's runs reproducible.  MLflow is the dependency group `ml`, imported only when a backtest logs, so the capture image doesn't carry it; `make dagster` adds it. MLflow's UI: `uv run --group ml mlflow ui --backend-store-uri sqlite:///mlflow.db`.

Determinism is required, not hoped for: `T` passed in, inputs sorted before predicting and before every mean, fixed seeds and LightGBM's deterministic mode with a fixed thread count once there is a trained model. Every run logs its git commit (and whether the tree had uncommitted changes), its image digest when there is one, and its months; its fidelity (`exact` or `approximate` by decision time, plan, Time machine) once `dwd_source_captures` gives capture start, and plots in step 7.
