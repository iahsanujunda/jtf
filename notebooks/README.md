# notebooks

Exploration only. No feature logic lives here: a feature worth keeping moves into a dbt model, so there is no pandas-to-SQL rewrite and no train/serve skew.

| Notebook | Reads | Purpose |
| --- | --- | --- |
| [00_source_probe](00_source_probe.ipynb) | The live sources, cached per day in `data/probe/` | How each source was probed, and how every finding became an extraction rule |
| [01_history_probe](01_history_probe.ipynb) | Historical files and APIs, cached per day in `data/probe/` | What history exists, how it differs from today's files, what loading it costs; the design of step 2 |
| [02_raw_to_ods](02_raw_to_ods.ipynb) | The prod raw bucket (read-only), cached in `data/raw-cache/` | How raw files become ODS tables: the row contract, versions and `known_at`, one parser per layout run over every file, the Dagster mapping |
| [03_solar_capacity](03_solar_capacity.ipynb) | METI's FIT/FIP disclosure site and archived copies of it, cached in `data/probe/capacity/`; TEPCO actuals from dev BigQuery | The solar capacity source end to end: when each release became known, how old the figure is when used, the TEPCO-area cut at the Fuji River, carrying vs extrapolating the stale figure, the weather-point weights |
| [04_ods_to_dwd](04_ods_to_dwd.ipynb) | The ODS tables in dev BigQuery | From ODS to DWD in SQL, for the solar path: capture start per source, versions and `known_at` of the target (a late backfill among them), which weather a forecast at `T` can use, hourly weather onto slots, the benchmark, and `as_of` as a range join over every decision time |
| [05_clear_sky](05_clear_sky.ipynb) | dbt's `dwd_tepco_actuals` in dev BigQuery (latest versions); pvlib as the reference | Clear-sky output in SQL: the sun's position against SPA, night by the sun against TEPCO's output, one sample per slot or six, clear days in time |
| [06_warehouse_against_sources](06_warehouse_against_sources.ipynb) | dbt's DWD models in dev BigQuery, every version, and the ODS manifest | Whether what step 5 built is true to its sources: `known_at` per source against the fetches that brought each version; one known day, target day 2026-11-17, traced by hand from the raw files through every layer |
| [07_ods_fingerprints](07_ods_fingerprints.ipynb) | ODS in dev BigQuery, its partition metadata, and a scratch dataset it makes and drops | Noticing an ODS row changed after its load: what the manifest records, a fingerprint per file, and which partitions a recheck after every load must read |
| [08_solar_label](08_solar_label.ipynb) | `ads_ml_label_solar` (the latest actuals), clear sky and capacity from `dws_solar_features`, the backtest's outcomes; TEPCO's curtailment reports | Whether delivered + curtailed is what the weather allowed: the curtailed figure against TEPCO's reported results, where curtailment sits, delivered output's fall at the edges of a curtailed run, and whether any label is unfit to train on (F6) |
| [09_output_against_clear_sky](09_output_against_clear_sky.ipynb) | The label and `dws_solar_features`; past output from `dwd_tepco_actuals` through `as_of`; forecast radiation from `dws_weather` | How output compares with flat-panel clear sky and whether that holds: a clear day's ratio by hour and season, its steadiness over three years, whether a model predicting MW runs out of range, baselines from the last week read as known at each decision time, clear and cloudy days, and the timing of forecast radiation |
| [10_what_the_forecast_knows](10_what_the_forecast_knows.ipynb) | `dws_weather` and `dws_solar_features` as known at each decision time; the label; `ads_ml_day_solar` for how each day turned out | Whether the weather forecast tells what kind of day tomorrow will be: forecast clearness against real clearness, by group and season, and a one-line rule that scales the seven-day mean by the forecast, checked for a leak |
| From 11 on | The dbt models in dev BigQuery, read through `as_of`; MLflow runs | Feature and model exploration on top of the pipeline: a feature that earns its place becomes a DWS model, so its logic lives only in dbt |

Run them with the notebook dependencies: `uv sync --group notebook`, then pick the `.venv` kernel in VS Code or Jupyter.
