# DWS

Features per (decision time, target slot), materialised for every decision time in one pass, so a full-history backtest is one query. Reads DWD only through the as-of macro. Features are append-only: changing what a feature means adds a new column; old columns go only when no production model uses them.

Phase 1: solar features (weather at the Kanto points, clear-sky output, D−2 lags, calendar, capacity).

What every slot of a decision time shares is a model of its own, one row per decision time: `dws_capacity`, the TEPCO area's installed solar on D as estimated at `T`, the least-squares line through the newest four releases known at `T` by quarter, with the newest figure carried beside it. It reproduces [notebook 03](../../../../notebooks/03_solar_capacity.ipynb)'s scores over the training window exactly (section 7: 0.44% mean error against 1.93% for the carried figure) and is computed in `NUMERIC`, so a rebuild gives the same figures to the bit. The features, the metrics' normalisation by capacity and the range checks read it. `dws_point_weights` holds each weather point's share of the newest release known at `T`: it weights the clear-sky radiation in `dws_solar_features.clear_sky_mw` (capacity × weighted clear sky ÷ 1000 W/m²), and later the weather.

`dws_weather` is the weather known at `T` for every slot of D, per point and model, from one source per target day: the first that covers all of D's daylight once its holes are filled. The order is the live capture, then lead 2, then per model the newest Single Run known strictly before `T`. Live comes first because a capture can only be added before `T`: a later top-up of Previous Runs, whose rule dates it before `T`, can't change what a past forecast saw. A hole is filled from the next model of the same source by the seed's fill order, and `<variable>_model` records whose value each is ([notebook 04](../../../../notebooks/04_ods_to_dwd.ipynb), sections 3.2, 3.4 and 3.6). The data test `dws_weather__every_daylight_slot_has_weather_at_t` is strict: every variable of every model, at every point, in every daylight slot. Today lead 2 serves 17 February 2024 to 15 November 2026, a Single Run 16 November, the live capture from the 17th. A rebuild reads 611 MB, each time the spine rebuilds.

The decision-time spine, `dws_decision_slots`, runs from the first target day to the day after the newest daily capture in `dwd_source_captures`. That read is the `as_of` rule's one named exemption ([rules](../../rules/README.md)): it decides which decision times exist and feeds no value, so later captures only add rows at the end.

`dws_fidelity` says how exact each decision time's inputs are: per decision time and input (`actuals_d2`, `weather`, `capacity`), the versions T read and how many are approximate ([notebook 06](../../../../notebooks/06_warehouse_against_sources.ipynb), section 3; PRD, Fidelity). Rule-dated actuals and weather from the history sources are approximate; a rule-dated capacity release whose files are unchanged since its `known_at` is exact, being as precise as a capture. It is fidelity from what T read, not from a date: D−2's actuals are exact from 09:00 on 2026-11-17, the weather from the 16th. A run is exact at T only where every input its model reads is, and `ads_runs` counts them.
