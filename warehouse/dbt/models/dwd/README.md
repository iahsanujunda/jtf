# DWD

Cleaned, typed detail per area and slot. Converts every power value to MW averaged over the slot and every slot label to its start time in JST. Keeps every version with its `known_at`, `known_until` and `basis`: a changed value is a new version, the same value seen again is not. Weather is kept per run, never collapsed. Range and slot checks here back F4 and F5.

`dwd_capacity_releases` has one row per quarterly capacity release, not per version: a release's date is one fact, so its `known_until` is always null and `as_of` reads it like any other model. A re-uploaded file is a new version of the release's figures, never a new date for the release ([notebook 04](../../../../notebooks/04_ods_to_dwd.ipynb), section 6).

The figures are the one input too large to rebuild every run (2 GB), so `dwd_capacity_area_files` is the only incremental model: it holds each raw file's MW per part of the area and reads only the files it doesn't hold at their newest parse, found by comparing the manifest with itself, not by a watermark. `dwd_capacity_area` versions them and is rebuilt in full. The figures per file have no `known_at`, so they are private to the dbt group `capacity_figures`: only `dwd_capacity_area` can read them, and dbt refuses any other `ref`. Sums are exact (`NUMERIC`): an incremental build must equal a full one to the bit, which the data test `dwd_capacity_area_files__every_parse_held` and a rebuild by hand check. The parts of the area are the seed `dim_tepco_area_parts`, each named by its weather point.

Weather is kept per source and per run, never collapsed, each model as the source gave it: a hole stays a missing hour, and DWS fills it from another model at the same lead ([notebook 04](../../../../notebooks/04_ods_to_dwd.ipynb), section 3.6). `dwd_weather_previous_runs` and `dwd_weather_single_runs` hold the hours as versions through one macro (`weather_versions`): each file as last parsed, a first version known by its rule (the hour − 24 h × lead + the model's delay; the run's start + the delay), a changed value known at the fetch that held it, never before the version it replaces. `dwd_weather_live` holds each daily capture as a forecast of its own, known at the fetch. `dwd_weather_slots` puts all three on 30-minute slots: radiation from the hour ending after the slot, the rest interpolated to its middle (section 3.5), a slot known once both its hours are and changed when either is. The delays and which model has radiation are the seed `dim_weather_models`. Previous Runs and Single Runs rebuild only when their history is topped up; the live capture rebuilds `dwd_weather_live` and the slots daily, a 278 MB read.

`dwd_tepco_forecast_next_day` holds TEPCO's own forecast for the next day (wind and solar together, demand, generation), known from the first evening capture that held it and always `captured`: TEPCO keeps no archive, so there is no history to date by a rule. It is known hours after the decision time of the day it forecasts, which a data test holds it to: it is a yardstick for a forecast, never an input. `dwd_jepx_spot` holds the spot prices per delivery slot, the Tokyo area's and the system's, by the rule (10:30 on the day before delivery) before capture start and by the fetch after; a price has never been seen to change, and a change would be a version. The price of a day is never known at that day's decision time, which another data test holds ([notebook 12](../../../../notebooks/12_tepco_forecast_as_yardstick.ipynb)).

`dwd_source_captures` holds every daily capture, one row per source and raw file fetched, known at the fetch: each versioned model takes its source's capture start from it (the first daily capture), and the decision-time spine in DWS its newest capture, so nothing above DWD reads the manifest. A capture is a fact of its own, so `known_until` is always null.

What has no source and no `known_at`, the sun and daylight, is in [DIM](../dim/).
